# Device codec capabilities and home cache — 2026-09-28

## Investigation
- The previous native profile advertised fixed codec support. A device could therefore receive a stream whose profile, level, dimensions, frame rate, or audio decoder exceeded its real MediaCodec capabilities and only recover after a visible playback failure.
- The Android 14 OnePlus Pad Go reports hardware H.264/HEVC/VP8/VP9 decoders, software AV1, platform AAC/AC3/E-AC3/E-AC3-JOC, and the packaged FFmpeg audio/video decoders. Its 4K HEVC Main 10 probe is rejected for profile/level, AV1 is rejected because there is no hardware decoder, and 1080p H.264 High is accepted by `c2.mtk.avc.decoder`.
- `MediaList.vue` fetched libraries, resume items, next-up items, and recent additions every time the home route was mounted, including normal navigation back from another page.

## Changes
- `NativeVideoPlugin` now exposes device codec/display metadata and a MediaCodec profile/level/size/rate probe. The Capacitor TypeScript contract and web stub expose the same API.
- Central codec detection maps Jellyfin codec/range metadata to Android MIME types, distinguishes hardware, software, platform-audio, and packaged FFmpeg support, and derives an automatic transcode bitrate from the physical display class.
- Native online playback probes the selected video and audio streams before requesting playback info. Unsupported video requests an H.264 server transcode; unsupported audio requests AAC while retaining video stream copy when possible. Forced automatic video transcodes use a bounded bitrate instead of the previous 1 Gbit/s ceiling.
- Android keeps MediaCodec as the preferred renderer and enables packaged FFmpeg extensions as fallback. AAC must use MediaCodec; E-AC3 Atmos/JOC requires explicit platform JOC support.
- Offline download compatibility uses the same runtime capability data and only keeps a software-decoded original video at 1080p or below.
- Video whose rotation-normalized dimensions exceed the physical display now requests a bounded server transcode even when MediaCodec reports that it can decode the source. Offline download selection applies the same rule.
- Review follow-up: the display size now comes from the active display mode's physical resolution (`Display.Mode.physicalWidth/Height`) instead of `displayMetrics`, which reports 1080p UI on 4K Android TV and excludes system bars on devices without edge-to-edge.
- Review follow-up: automatic native transcodes of sources larger than the display add `maxWidth`/`maxHeight` (oriented like the source) to the Jellyfin TranscodingUrl, so the output is actually display-sized instead of relying on the bitrate cap alone.
- Review follow-up: auto-detected download transcodes of oversized sources are bounded to the display size and to the recommended bitrate (never above the source); previously they re-encoded to H.264 at the source resolution with no bitrate cap.
- Review follow-up: leaving the player marks the home snapshot stale; returning home keeps it rendered and refetches in the background without a spinner.
- The home page keeps a per-server/user in-memory snapshot across route changes. A refresh button in the header explicitly refetches all four home data groups while preserving the rendered snapshot during the request.
- Logging and README documentation describe the selected capability/fallback path and the new home refresh behavior.

## Audio track support (versionCode 262)
- Removed the browser-oriented `IsSecondaryAudio` conditions from the native device profile only: ExoPlayer selects non-default tracks inside a DirectPlay file itself. The web profile keeps them.
- `withDeviceAudioCodecs()` restricts the native profile's video DirectPlay/Transcoding audio codec lists to what the device decodes (MediaCodec, or FFmpeg except AAC). A DirectPlay profile left with no codec is dropped, because an empty `AudioCodec` means "any" to Jellyfin; a transcode target falls back to AAC. Download transcode requests use the same filter, so stream-copied offline audio is decodable. Without capabilities (web preview) the profile is unchanged.
- `NativePlayerActivity.selectAudioTrack` checks `Tracks.Group.isTrackSupported` before switching. An unsupported track goes straight to the existing `audioError` → server audio transcode restart instead of crashing first; the crash fallback stays for failures that only appear at decoder/AudioSink init.
- Verification: 97 Vitest tests passed (3 new profile-filter tests), `npm run build` succeeded, Docker built versionCode 262 (SHA-256 `923fdc69db56749a6ba364501a7623e58c9dc2025bde95017fd6dc53994410c7`), installed on the OnePlus Pad Go with data preserved.
- 8 Mile with preferred language `eng` (secondary AC3 5.1 track): Jellyfin now answers `SupportsDirectPlay=true`, the session reports `DirectPlay` with no transcode, the app switched ExoPlayer to the English track after the support check, `c2.dolby.eac3.decoder` decoded it, and playback progressed in real time. A mid-playback switch to the French AAC 2.0 track used `c2.android.aac.decoder` and playback continued. The tablet decodes every advertised audio codec (MediaCodec, or FFmpeg for MP2/DTS/TrueHD), so the unsupported-track path is covered by unit tests only, not on a device. 8 Mile's UserData was restored exactly afterwards.

## Atmos and audio track choice (versionCode 263)
- Films4K test (22 of 35 films carry Atmos: 19 TrueHD-only, 2 E-AC3-only, Dune: Part Two both). On the tablet every one needs a video transcode (no HEVC Main 10 decoder), and the native HLS transcoding profiles only accepted AAC, so E-AC3 Atmos was converted to AAC 5.1 although the tablet declares `audio/eac3-joc`.
- Native HLS video transcoding profiles now list `aac,eac3,ac3` (AAC first as the encode target); `withDeviceAudioCodecs` removes E-AC3/AC3 on devices without them. Download transcodes also allow `eac3`.
- New `src/utils/audioTrackSelection.ts`: `pickPreferredAudioStream` keeps language priority (per-item choice, then global preference, then default, then first) and only among the matching language's tracks ranks native decoder > FFmpeg > server transcode, then decodable Atmos, channels, default flag; commentary tracks are skipped unless they are the only match. Without capabilities (web preview) the first language match is kept. Per-item choices stored by ExoPlayer as 2-letter codes (`en`) now match Jellyfin's 3-letter codes via `languageMatches` (previously never matched).
- DirectPlay: `tracksReady` selects the ExoPlayer group of the exact Jellyfin stream chosen at startup (`nativeAudioGroupFor`, container order), falling back to the previous language matching. User track switches in transcoded playback only force an AAC transcode when the target track is not decodable, so switching to an E-AC3 Atmos track keeps it.
- Verification: 106 Vitest tests in 15 files passed (9 new selection tests), `npm run build` succeeded, Docker built versionCode 263 (SHA-256 `9e236b2017dbdb58e18591f3c3a7c887cb8201285f578bb36d9f4988dcf5118d`), installed on the tablet with data preserved.

## Frozen WebView during native playback (versionCode 266)
- Report: on the tablet, audio and subtitle changes did nothing during Contagion (HEVC Main 10, transcoded). Logcat showed the native picker emitting `audioSwitchJellyfin`, but no JS handler ran. A CDP probe on the hidden page showed a 50 ms `setTimeout` and a `MessageChannel` task never running while microtasks did (Chrome WebView 153): Chromium freezes the hidden page roughly 45–60 s after `NativePlayerActivity` covers `MainActivity`. Returning home unfroze it and replayed eight queued switches at once (one restart from a stale 6:09 position, several stacked back presses). Progress reporting, burn-in restarts, and quality switches were affected the same way.
- Fix: `NativePlayerActivity` uses a translucent theme (`AppTheme.NativePlayer`) so `MainActivity` stays visible (paused, not stopped) and its page is never hidden; the player layout is opaque black. The sensor-landscape orientation moved from the manifest to `onCreate` and is skipped on Android 8.0, which rejects fixed orientations on translucent activities.
- Verification on the tablet (versionCode 266, SHA-256 `dca3c8817439505de1b23c6cbf20466428d46f2cad3b0698b17666110a329c83`): after 130 s of Contagion playback the page stayed `visible` with timers running. Switching audio ENG → FRA ran the JS handler within 10 ms, restarted at the current position (16:28) with AC3 copied (`direct=true`), and left a single player activity. French SRT subtitles rendered immediately; French PGS restarted with `SubtitleStreamIndex=7` at 17:32 and rendered burned-in. The user's resume position (12:57), UserData, and per-item track keys were restored afterwards and the home snapshot refreshed.
